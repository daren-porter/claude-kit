- **Guard the remaining unbounded `openSync` calls in session-start.js (2026-08-07).** A bounded read bounds bytes, not time: `openSync` on a FIFO blocks until a writer appears, and the security reviewer hung the hook for 5 seconds this way before killing it, against a file header that promises "Never blocks". S4 added the `statSync(...).isFile()` guard to its own helper only. Four pre-existing readers in that file still lack it: `countPendingKaizen` (the notes read), `findCompletedUnarchived`, the plan scan in `main()`, and `claudeMdSyncOffer`, which carries two of them (its `statSync` checks size and not `isFile`, so the asset `readFileSync` blocks just as an `openSync` would, and the version-marker `openSync` is unguarded). `hooks/kit-goal-lib.js:44-48` carries the guarded idiom with a comment naming the hazard. Not exploitable under the kit's trusted-workspace premise; it is a self-inflicted-hang risk, so fix it the next time that file is open. Use the atomic form for the sweep rather than copying S4's stat-then-open: open with `O_RDONLY | O_NONBLOCK` and check `fstatSync(fd).isFile()`, which closes the TOCTOU window the finishing security review noted and is a no-op for regular-file reads.
- **Replace `process.exit(0)` after a stdout write with `process.exitCode = 0` (2026-08-07).** Forcing the exit can discard a stdout write still in flight on a pipe. Four hooks have the shape: `session-start.js`, `stop-docs-hygiene.js`, `branch-reaper-nudge.js`, and `kit-goal-stop.js`. The last is the one that matters: a truncated write reads as no-block, which releases the goal leash silently and defeats the completion contract it exists to hold. Found and confirmed during the 2026-08-07 adoption pass (Scott fixed the same shape across six hooks in his kit). Out of scope for the pass itself; fix on its own.
